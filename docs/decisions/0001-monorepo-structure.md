# 0001. 采用 Monorepo 项目结构

**状态**: 🟢 已采纳
**日期**: 2026-01-30

## 背景

本项目包含多个紧密相关的应用：
1.  面向公众的官网 (Website)
2.  内部使用的管理后台 (Management)
3.  客户使用的服务门户 (Customer Portal)
4.  提供 API 的后端服务 (Backend)

这三个前端应用之间共享大量的类型定义 (TypeScript Interfaces)、工具函数和 UI 组件样式。如果将它们拆分为独立仓库，代码复用将变得极其困难，版本管理也会非常繁琐。

## 选项

1.  **Multi-repo (独立仓库)**
    *   利: 权限控制简单，构建独立。
    *   弊: 共享代码难维护（需要发 npm 包或 git submodule），依赖版本不一致问题严重。

2.  **Monorepo (单体仓库)**
    *   利: 代码共享极其方便（直接引用本地 workspace），所有项目依赖原本统一，重构原子性（一次提交修改所有相关项目）。
    *   弊: 构建工具配置稍显复杂，仓库体积较大。

## 决策

选择 **Monorepo** 结构，使用 `npm workspaces` 进行管理。

我们将建立 `@tonghai/shared` 包，并在所有前端项目中引用它。

## 后果

*   [+] `packages/shared` 修改后，可以立即在消费端应用中生效，无需发包。
*   [!] 需要确保根目录 `package.json` 正确配置了 `workspaces`。
*   [!] 开发时需注意不要在 `shared` 中引入特定平台的依赖。
