# 通海南洋 CRM — 全面改进规划

> **版本**: v1.0  
> **日期**: 2026-03-20  
> **审阅轮次**: 5 轮（架构 → 后端服务 → API 路由 → 前端 → 安全与运维）  
> **审阅范围**: 全仓库（86 后端 TS 文件 + 96 管理前端文件 + 38 客户门户文件 + 30 官网文件）  
> **⚠️ 本规划仅供参考，未修改任何代码**

---

## 第一部分：代码质量改进

### 🔴 P0 — 必须修复（阻塞稳定运行）

| # | 问题 | 文件 | 说明 |
|---|------|------|------|
| 1 | **官网 SSG 构建失败** | `packages/website` | `DOMPurify.sanitize` 在 SSR 环境下无 DOM，需用 `isomorphic-dompurify` 或条件导入 |
| 2 | **测试用例失败** | `backend/src/__tests__/notificationService.test.ts` | `vi.mock` factory 中引用了 hoisted 之前初始化的变量，需在 factory 内直接创建 `vi.fn()` |
| 3 | **Docker Compose 硬编码密码** | `docker/docker-compose.yml` | PostgreSQL 密码 `crm_password` 明文写死，需改为 `${POSTGRES_PASSWORD}` 环境变量注入 |
| 4 | **JWT_SECRET 默认值** | `backend/src/config/env.ts` | 非生产环境 fallback 为 `'dev-secret-only-for-development'`，如果生产 `.env` 漏配会直接用弱密钥。建议：即使开发环境也强制要求设置，或在启动日志中用 🔴 警告 |

### 🟠 P1 — 应该改进（影响性能/安全/可维护性）

| # | 问题 | 文件 | 说明 |
|---|------|------|------|
| 5 | **管理端 JS 包 1.2MB** | `packages/management` | 无路由懒加载、Element Plus 全量引入、ECharts 全量引入。需配置 `manualChunks` + 动态 `import()` + Element Plus 按需 |
| 6 | **软删除过滤不统一** | 多个 Service | `Lead`, `Customer`, `Project`, `Task`, `Document` 有 `deletedAt`，但 `Invoice`, `Appointment`, `Activity` 等没有。建议：要么全部加，要么用 Prisma Middleware 统一过滤 |
| 7 | **Invoice Service 大量 `any`** | `invoiceService.ts` | `updateData: any`, `invoice as any`, 税率类型断言等。需补全类型定义 |
| 8 | **Document Service 上传权限弱** | `documentService.ts` | 注释写了"简化起见，先直接写入"，无项目所有权校验。客户可上传到任意项目 |
| 9 | **排序字段未校验** | `routes/leads.ts` | `sortBy` 直接拼进 Prisma `orderBy`，可能导致注入任意字段排序。需白名单校验 |
| 10 | **内存黑名单不持久** | `config/redis.ts` | Redis 断开后降级到 `memoryBlacklist`（进程内 Map），多实例部署时无法共享，且重启丢失。可接受降级但需文档说明局限 |
| 11 | **WorkflowService N+1 查询** | `workflowService.ts` | `getTeamWorkload()` 对每个用户单独查 lead count + task count，用户多时查询数 = N×2。可用 `groupBy` 一次聚合 |
| 12 | **Lead 详情无分页** | `leadService.ts` | `getLeadById` 取 `tasks: { take: 10 }` 和 `activities: { take: 20 }`，无分页参数，数据量大时性能差 |
| 13 | **无 Refresh Token 轮换** | `authService.ts` | 每次 refresh 返回同一 token，若 token 泄露可持续刷新。建议实现 RT 轮换（每次刷新旧 token 失效、签发新 token） |
| 14 | **CORS 仅白名单无正则** | `config/env.ts` | `cors.origins` 是精确匹配数组，如果有子域名部署（如 `*.thny.sg`）会失败。支持正则或通配符 |
| 15 | **文件上传无类型/大小前端校验** | `routes/documents.ts` | 后端 multer 有大小限制，但前端无预校验，用户选完大文件才报错 |

### 🟡 P2 — 可以优化（锦上添花）

| # | 问题 | 说明 |
|---|------|------|
| 16 | **Prisma 5.8 → 最新版** | 新版有性能改进和 bug 修复 |
| 17 | **缺少 E2E 测试** | 目前只有单元测试，关键流程（登录→创建线索→转化→开票）无端到端测试 |
| 18 | **Swagger 覆盖率** | 部分路由缺少 `@swagger` 注解，需补全 |
| 19 | **日志 RequestId** | 每个请求未生成 UUID 贯穿日志链路，排障困难 |
| 20 | **共享包 (`@tonghai/shared`)** | 目前只有类型导出，可扩展共享校验逻辑、常量、工具函数 |

## 第二部分：功能改进建议

### A. 管理后台 — 功能增强

#### A1. 🤖 AI 能力深化
| 功能 | 说明 |
|------|------|
| **AI 邮件撰写** | 基于线索上下文自动生成跟进邮件草稿（已集成 OpenAI，扩展 prompt 即可） |
| **AI 会议纪要** | 会议结束后上传录音/文字，自动生成结构化纪要和待办 |
| **AI 竞品分析** | 输入公司名，自动抓取公开信息并生成分析摘要 |
| **智能预测** | 基于历史数据预测下季度营收、线索转化概率（当前 analyticsService 趋势是静态统计） |

#### A2. 📊 高级分析
| 功能 | 说明 |
|------|------|
| **客户生命周期价值 (CLV)** | 追踪单个客户从线索到全部项目累计贡献的营收 |
| **销售团队目标管理** | 设定月/季度目标，实时追踪达成率 |
| **流失预警** | 基于"最后联系时间 + 项目状态 + 账单逾期"自动标记高风险客户 |
| **自定义仪表盘** | 允许用户拖拽配置自己的 Dashboard 布局和指标卡片 |
| **同比/环比对比** | 所有趋势图表支持 YoY/MoM 对比 |

#### A3. 🔄 自动化增强
| 功能 | 说明 |
|------|------|
| **邮件序列 (Drip Campaign)** | 线索进入特定阶段后自动发送 3-5 封培育邮件 |
| **定时提醒升级** | 线索 X 天未跟进 → 自动提醒负责人 → Y 天后升级到主管 |
| **自动合同生成** | 线索转化时基于模板自动生成服务合同 PDF |
| **审批流引擎增强** | 当前报销有审批，但发票、合同、折扣审批也需支持 |
| **批量操作** | 批量分配、批量改状态、批量发邮件 |

#### A4. 📱 通讯集成
| 功能 | 说明 |
|------|------|
| **WhatsApp 集成** | 新加坡企业客户高频使用 WhatsApp，可直接从 CRM 发消息 |
| **日历同步** | 与 Google Calendar / Outlook 双向同步会议 |
| **邮件收发** | 管理端直接收发邮件（IMAP/SMTP），自动关联到线索/客户 |
| **电话集成** | 集成 VoIP（如 Twilio），点击拨号、通话录音、自动记录 |

#### A5. 📄 文档与合同
| 功能 | 说明 |
|------|------|
| **电子签署增强** | 已有 DocuSign 集成，可扩展支持更多签署平台 |
| **合同模板管理** | 预设合同模板，变量替换自动生成 |
| **文档版本控制** | 当前文档是覆盖式更新，需支持版本历史 |
| **OCR 识别** | 上传名片/身份证自动识别填入客户信息 |

### B. 客户门户 — 功能增强

#### B1. 🎯 客户自助
| 功能 | 说明 |

#### B3. 📈 项目可视化

## 第四部分：技术债务清理清单

| 项目 | 当前状态 | 建议 |
|------|----------|------|
| TypeScript `any` | ~15 处 | 逐步替换为具体类型 |
| 软删除 | 不统一 | Prisma Middleware 统一处理 |
| 错误码 | 混合中英文 | 统一错误码体系（i18n-ready） |
| 共享包 | 仅类型 | 扩展为共享校验 + 常量 + 工具 |
| 环境配置 | `.env.example` 不完整 | 补全所有可选变量说明 |
| 依赖版本 | 部分旧 | 季度性依赖更新审查 |
| Redis 降级 | 内存 Map | 文档化局限，评估 Redis Sentinel/Cluster |
| 数据库迁移 | 使用 `db push` | 切换为正式 `prisma migrate` 流程 |

## 第五部分：关键指标建议

上线后建议追踪这些指标来衡量改进效果：

| 指标 | 当前值 | 目标值 |
|------|--------|--------|
| 管理端首屏加载 (FCP) | ~3-4s（预估） | <1.5s |
| 线索→客户转化率 | 需采集 | >25% |
| 平均跟进响应时间 | 需采集 | <24h |
| 客户门户月活率 | 需采集 | >60% |
| API 平均响应时间 | 需采集 | <200ms |
| 测试覆盖率 | 低 | >70% |
| 构建成功率 | 部分失败 | 100% |
